# Phase 2 — UI Design Contract

> Visual and interaction contract for the public read surfaces: home/today, per-date view, trip picker, boat detail, compare, trends, about. Generated by gsd-ui-researcher in auto mode. Verified by gsd-ui-checker.

This contract is the visual source of truth for Phase 2 implementation. It honors every locked decision in `02-CONTEXT.md` (D-01..D-34) and every non-negotiable in `CLAUDE.md` (especially #4 per-angler framing and the anti-features list). The v1 polish bar is "shareable with friends," not public-launch — this contract is intentionally minimum-viable, not maximalist.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none |
| Preset | not applicable |
| Component library | none (hand-built Svelte 5 components, Tailwind 4 utility classes) |
| Icon library | none for v1 — use unicode glyphs only when essential (`›`, `‹`, `▼`, `▲`, `↗`). FLAG: revisit if icon count exceeds 5 in implementation; lucide-svelte is the recommended add. |
| Font | system-ui stack (no web-font fetch). Declared in `app.css` `@layer base`: `-apple-system, BlinkMacSystemFont, "Segoe UI", Roboto, "Helvetica Neue", Arial, sans-serif`. Tabular numerals (`font-variant-numeric: tabular-nums`) on every per-angler number, n=X label, and chart axis tick. |

**Rationale for "none":** shadcn-svelte exists but Phase 2 is the ground floor of the UI and ships only 7 routes with ~6 reusable components. Hand-building the small surface area is faster than adopting a registry, and locks fewer downstream decisions. shadcn-svelte adoption can be revisited at Phase 5 polish if the component count grows.

**Tailwind 4 setup (existing):** `@import 'tailwindcss'` in `src/app.css`. Tokens declared via `@theme` directive (Tailwind 4's CSS-first config) — see Color and Typography sections for the exact `@theme` block.

## Spacing Scale

All spacing values are multiples of 4 (Tailwind 4 default, 1 unit = 4px).

| Token | Value | Tailwind | Usage |
|-------|-------|----------|-------|
| xs | 4px | `1` | Icon-to-label gap, chip inner padding-y |
| sm | 8px | `2` | Compact element spacing, table cell padding-y, inline badge gap |
| md | 16px | `4` | Default element spacing, card inner padding (mobile), form-field vertical gap |
| lg | 24px | `6` | Section padding, card inner padding (desktop), filter-bar bottom margin |
| xl | 32px | `8` | Layout gaps between major sections on a page |
| 2xl | 48px | `12` | Page-level top padding (desktop), gap between page header and first section |
| 3xl | 64px | `16` | Top of the home/today hero block (desktop only); below `md:` only |

**Layout containers:**
- Mobile (default, ≥375px): `px-4` page gutter (16px), `max-w-full`.
- Tablet (`sm:` ≥640px): `px-6` page gutter (24px).
- Desktop (`md:` ≥768px): `px-8 max-w-6xl mx-auto` (32px gutter, 1152px max content width).
- Tables on narrow viewports use horizontal-scroll containers (`overflow-x-auto`) — never let body content cause horizontal page scroll at 375px (BRW-08).

**Touch targets:** every interactive element (buttons, filter selects, prev/next nav, expand toggles) has a minimum hit area of 44×44px on mobile. Use `min-h-11` (44px) on buttons; padding-only sizing is insufficient.

**Exceptions:** none.

## Typography

Mobile-first base size 16px, line-height 1.5. Exactly 4 sizes, 2 weights (400 regular, 600 semibold). No italics. No 3+ font weights.

| Role | Size | Weight | Line Height | Tailwind | Usage |
|------|------|--------|-------------|----------|-------|
| Body | 16px | 400 | 1.5 | `text-base font-normal leading-normal` | Default body text, table cells, paragraphs, form labels |
| Label | 14px | 600 | 1.4 | `text-sm font-semibold leading-tight` | Filter labels, table column headers, badge text, "n=X trips" |
| Heading | 20px | 600 | 1.25 | `text-xl font-semibold leading-tight` | Section headings, card titles, "Why this boat?" panel header |
| Display | 28px | 600 | 1.2 | `text-3xl font-semibold leading-tight md:text-4xl md:leading-tight` | Page titles ("Today's Counts", "Trip Picker", boat name on detail page); 36px on `md:` |

**Tabular numerals are mandatory** on:
- Every per-angler value rendered by `<PerAnglerMetric>` (the value + unit).
- Every `n=X` label.
- Every count column in tables (anglers, species_count).
- Every chart axis tick + tooltip number.

Implementation: `class="tabular-nums"` on the rendering element. Tailwind 4 ships this utility natively.

**Decimal precision rule (CLAUDE.md non-negotiable #3 + Phase 2 specifics):**
- Per-angler values: integer when ≥10, one-decimal when <10. Never two decimals. Never trailing-zero artifacts ("4.0" renders as "4", "4.50" renders as "4.5").
- Counts (anglers, species_count): always integer.
- Heatmap cell labels (when shown on hover): one-decimal max.
- The `<PerAnglerMetric>` component owns the formatting; do not format per-angler values inline.

**Accent reserved for (explicit list — every other use of accent is a contract violation):**
1. Text links to internal routes (`/picker`, `/about`, boat detail, source-site links).
2. Primary CTA buttons: "Find boats" on `/picker`, "Compare" on `/compare`, "View trends" on `/trends`.

- Per-angler metric values (those are body text color).
- Provisional badges (amber).
- Low-data badges (gray).
- Filter chips / pills (those use neutral surfaces).
- Heatmap cell coloring (viridis only).

### Heatmap palette (viridis-like) — accessibility

The 5-stop viridis ramp is colorblind-safe (perceptually uniform across deuteranopia + protanopia; verified via Color Universal Design references). However, color alone is NOT a state signal:

- Every heatmap cell exposes its value + n via tooltip on hover (and via `aria-label` for screen readers / keyboard focus).
- Insufficient-data cells (n<5) render with `--color-lowdata-bg` (#e5e7eb gray) AND a `■` glyph / striped overlay AND tooltip text "low data — not enough trips". Three signals, not just color.
- Legend is always visible below the chart with units ("fish/angler") and a separate "low data" swatch.

### Provisional badge

- Text: "provisional — boats still reporting"
- Position: inline next to the date heading + on each row of today's table.
- Visual: amber background (`--color-provisional-bg`), amber-700 text, 14px semibold, 4px corner radius, 8px horizontal padding, 2px vertical padding.
- Rule: rendered if and only if `source_date === today() PT` (D-20). Past dates: no badge (final by calendar).

### Low-data badge

- Text: "low data"
- Position: adjacent to per-angler value, after the unit ("4.2 fish/angler · low data · n=3 trips").
- Visual: gray background (`--color-lowdata-bg`), gray-500 text, 14px semibold, 4px corner radius, 8px horizontal padding, 2px vertical padding.
- Rule: rendered when `nTrips < 5`. Owned by `<PerAnglerMetric>`.
- Critical: low-data rows are NEVER hidden (TRP-07). Always rendered; flagged not filtered.

### "Last scraped at" indicator (BRW-03)

- Text format: "Last scraped at [HH:MM] PT"
- Time format: 24-hour, leading zero ("23:04 PT", not "11:04pm PT").
- Position: top-right of the page header on every data-showing page. On mobile (<sm:), drops below the page title on its own line.
- Visual: `text-text-subtle` (#64748b), 14px regular, with a subtle clock prefix glyph optional (FLAG: omit for v1, no icon library yet).
- Source: `scrape_runs` most recent `outcome IN ('success','empty')` `finished_at`, formatted via `dates.ts` helper.
- Failure case: if no scrape has ever succeeded (scrape_runs empty), render "No scrape data yet" in muted gray. Phase 5 polishes this further.

### Disclaimer / "About the data" page (`/about`) — full copy

Verbatim copy required. The planner may break this into headings + paragraphs with sensible Tailwind prose styling, but the wording must match.

```
About the data

Where the data comes from

FishCount aggregates publicly posted dock totals from sandiegofishreports.com. We
scrape that source nightly at 23:00 PT, store the counts in our own database, and
re-render them in views the source site doesn't offer (trip pickers, calendars,
trends, comparisons).

We never modify the source numbers. Every row links back to the source page so you
can verify it.

What "fish/angler" means

The dock-total report tells you a boat caught X fish for Y anglers on a trip. Our
"fish/angler" metric is X ÷ Y — the boat's per-angler yield on that trip, averaged
across multiple matching trips when we rank or summarize.

This is a derived boat-aggregate average, not an individual attribution. The boat
that caught 50 yellowtail with 25 anglers gets credited 2.0 fish/angler. We don't
know which anglers caught what, and we don't claim to. Some anglers caught more,
some caught fewer, some caught zero.

Use this number to compare boats on similar trips, not to predict your own catch.

Why trip type matters

A 1/2 Day AM trip and a Long Range trip catch fundamentally different fish in
fundamentally different volumes. We never compare per-angler numbers across
different trip types. The trip-type filter is required for a reason.

Sample size and "low data"

Every per-angler number we show comes with n=X — the count of trips that fed the
average. When n is below 5, we flag the row as "low data" and trust you to read
it skeptically. We don't hide it; we flag it.

In Phase 3 we add forecast projections, and we will refuse to render a point
estimate when n<5 — only the historical record will show.

Data gaps

If our scraper missed a day, we render that day as a gap, not a zero. A boat with
zero anglers reported is missing data, not a zero-fish trip.

How fresh is the data

The "Last scraped at" indicator at the top of every data page tells you when the
most recent scrape finished. Today's data is labeled "provisional" until the day
rolls over — boats are still reporting.

Contact

Reach out: [contact pointer — populated in Phase 5].
```

## Component Contracts

Six reusable Svelte 5 components live under `src/lib/components/`. Each has a strict prop contract. Implementation lives in Phase 2 plans; this contract is the visual spec.

### 1. `<PerAnglerMetric>` (D-16, TRP-04, BRW-09 — MANDATORY)

**File:** `src/lib/components/PerAnglerMetric.svelte`

**Props:**
```ts
{
  value: number;        // raw weighted avg, NaN-safe
  nTrips: number;       // count of trips backing the average
  ctx?: 'row' | 'card' | 'hero';  // size/layout context, default 'row'
  showFraming?: boolean; // first instance per page only — see PerAnglerFramingProvider
}
```

**Rendering rules:**
1. Format `value`:
   - If `Number.isNaN(value)` or `value === null` or `nTrips === 0`: render "—" (em-dash) and skip everything else (no badges, no n label).
   - Else if `value >= 10`: render integer (`Math.round(value)`).
   - Else: render one decimal (`value.toFixed(1)`), trim trailing ".0" — so 4.0 → "4", 4.5 → "4.5".
2. Append unit label: `" fish/angler"` (literal, with space).
3. Append `n` label: `" · n=" + nTrips + " trips"` (or "1 trip" for nTrips===1, no other plural exceptions).
4. If `nTrips < 5` AND `nTrips > 0`: insert "low data" badge between unit and n-label: `" · low data · n=3 trips"`.
5. If `showFraming` is true (set automatically on first instance per page via Svelte context): below the metric line, render the inline framing: `<small class="block text-text-muted">derived boat-aggregate average, not individual angler — <a href="/about" class="text-accent underline">About the data</a></small>`.
6. Wrap value+unit in `<span class="tabular-nums font-semibold">…</span>` for consistent number alignment.

**Layout by `ctx`:**
- `row` (default): inline span, single line. Fits in table cells.
- `card`: block, value emphasized at `text-xl`, n-label and badge wrap to second line on mobile.
- `hero`: block, value at Display size (`text-3xl`), n-label below at body size.

**Anti-patterns enforced (component refuses to render):**
- A per-angler value with no `nTrips` prop → render "—" instead.
- A per-angler value with two-decimal precision → component formats; caller cannot inject formatted strings.
- A per-angler value WITHOUT framing on the first page instance → `<PerAnglerFramingProvider>` parent assertion warns in dev.

**Framing provider:**
Wrap the page or a section in `<PerAnglerFramingProvider>` (a tiny Svelte 5 context-set component). The first child `<PerAnglerMetric>` automatically gets `showFraming=true`; all subsequent instances on the same page get false. This satisfies "framing must appear inline on every page" without spamming it on every row.

## Interaction Contracts

### Filter changes
1. User changes a `<select>` or input value.
2. JS handler reads the new value, builds new `URL` from `$page.url`, sets/deletes the relevant `searchParams` key.
3. Calls `goto(url, { keepFocus: true, replaceState: true, noScroll: true })`.
4. SvelteKit reruns `+page.server.ts` `load()`; new HTML streams in.
5. URL is shareable (D-18).

No `<form>`-submit + page-reload pattern; everything is `goto()`-driven.

Exceptions: the `<input type="date">` on `/picker` and the multi-boat `<select multiple>` on `/compare` pair with an explicit "Find boats" / "Compare boats" submit button to avoid noisy URL churn while the user is mid-edit.

### "Why this boat?" expand
- Pure client-side `let expanded = $state(false)` toggle on `<BoatCard>`.
- No fetch, no URL change. All panel data is already in the loader result (D-28).
- Animation: `transition:slide` (Svelte 5 built-in) at default duration. No fancy easing.
- ARIA: button has `aria-expanded` + `aria-controls` pointing to the panel's id.

### Date picker navigation (`/date/[d]`)
- Previous/Next: text links to `/date/[d±1]`. Disabled (muted, no underline) at dataset bounds.
- Date input: `<input type="date">` with `min` + `max` from dataset bounds. On change, `goto('/date/[chosen]')`.
- "Today": text link to `/`.

### Chart rendering lifecycle
1. SSR: server passes `option` JSON to `<Chart>`. SSR renders the loading skeleton + `aria-label`.
2. Hydration: `onMount` dynamic-imports ECharts modules.
3. First paint: chart instance attaches to DOM, renders.
4. Resize: ResizeObserver re-renders on width changes.
5. Filter change: URL changes → page rerenders → `<Chart>`'s `option` prop changes → chart `setOption(newOption)` (not full destroy/recreate).
6. Unmount: dispose instance.

### Top nav
- 4 links inline: "Home", "Picker", "Trends", "Compare", "About". (5 links — count corrected.)
- Active link has `text-accent` + no underline; inactive has `text-text-muted` + hover underline.
- No hamburger menu in v1 (D-31). Wraps to two lines on very narrow viewports (acceptable).
- Sticky on `md:`, static on mobile.

### Loading states (Phase 2 minimum)
- SSR pages render their final HTML in one pass — there is no client-side "loading" UI for first paint.
- Chart components show their loading skeleton until ECharts hydrates (typically <300ms).
- Filter changes use `goto()` which triggers SvelteKit's built-in pending-navigation state — no additional spinner in Phase 2 (FLAG: Phase 5 may add a top-of-page progress bar via `$navigating` store).

## Accessibility

### Keyboard navigation
- Every interactive element is keyboard-reachable in source order (no `tabindex` shenanigans).
- Tab order on every page: top nav → page header (skip if no interactive elements) → filter bar (left-to-right, top-to-bottom) → content region (table rows → expand toggles → links) → footer.
- Focus-visible ring: `focus-visible:outline-none focus-visible:ring-2 focus-visible:ring-[--color-accent] focus-visible:ring-offset-2`. Applied via base styles in `app.css` for `<a>`, `<button>`, `<input>`, `<select>`, `[tabindex]`.
- "Skip to main content" link at very top of every page (visually hidden until focused). Targets `<main id="main">`.

### Screen readers
- Every chart has a meaningful `aria-label`.
- Tables use `<table>`, `<thead>`, `<tbody>`, `<th scope="col">`. No layout tables.
- Per-angler values include the n=X label inline; screen readers read the full sentence ("4.2 fish/angler · low data · n=3 trips") in one pass.
- Provisional badges and low-data badges have `<span aria-label="provisional, boats still reporting">provisional</span>` — the visible short form plus the verbose aria-label.
- Expand toggles have `aria-expanded` + `aria-controls`.
- All decorative glyphs (`›`, `‹`, `▼`) have `aria-hidden="true"`.

### No color-only state signaling
- Provisional state: amber color + amber background + literal text "provisional". Three signals.
- Low-data state: gray color + gray background + literal text "low data" + `n=X` label. Four signals.
- Heatmap insufficient-data cells: gray color + gray background + tooltip "low data — not enough trips" + visible legend entry. Four signals.
- Active nav link: accent color + bold-ish weight (semibold via Label typography). Two signals (color + weight; the underlying tag is the same `<a>`).

### Color contrast
- All text meets WCAG AA (4.5:1) minimum on all background combinations declared in the Color section.
- See Color section for verified ratios.

### Reduced motion
- Honor `prefers-reduced-motion: reduce`: disable Svelte `transition:slide` and ECharts entry animations.
- Implementation: a single CSS rule in `app.css`:
  ```css
  @media (prefers-reduced-motion: reduce) {
    * { animation-duration: 0.01ms !important; transition-duration: 0.01ms !important; }
  }
  ```
- ECharts: pass `animation: false` to `option` when `window.matchMedia('(prefers-reduced-motion: reduce)').matches`.

### Touch targets
- Minimum 44×44px on all interactive elements (mobile).

## Anti-Feature Guards (UI patterns this phase REFUSES to render)

This phase is not allowed to render any of the following. Checker MUST flag any occurrence:

1. **"ON FIRE", "HOT BITE", "Hot day", flame emoji, fire icons** anywhere in UI strings. (Phase 4 has a "hot day" alert email — that's a server-side concept, never a UI badge.)
2. **Trophy / medal / star icons** for ranking. Picker results show position number ("#1", "#2") only — no ⭐ or 🏆.
3. **Leaderboard framing** ("Top 10 boats this season"). Picker is a query result, not a leaderboard.
4. **"Sponsored" / "Featured" / "Promoted" boat slots.** Ranking is strictly by weighted fish/angler within trip-type filter (D-08) — no paid placement.
5. **2-decimal per-angler numbers** ("4.25 fish/angler"). One decimal max. Component enforces.
6. **Per-angler metric without inline framing** on first instance per page. `<PerAnglerFramingProvider>` enforces.
7. **Cross-trip-type comparison.** Compare and trends pages enforce a single trip type. Picker enforces a single required trip type. There is no UI affordance to mix.
8. **Red/green hot/cold heatmap palette.** Viridis only.
9. **Hidden low-data rows.** TRP-07 violation. Low-data is flagged, never filtered.
10. **Manual scrape trigger.** No "Scrape now" button anywhere in v1.
11. **"Last refresh: just now" / live-update polling.** Data is as fresh as the most recent scrape; UI says so via "Last scraped at" — no faux real-time UI.
12. **Modal-only filter UIs.** All filters live in URL state (D-18). No filter that disappears on modal close.
13. **Dark mode toggle.** Single light theme in v1. (FLAG: Phase 5 may add.)
14. **Account / login UI.** Public anonymous browsing only. (Phase 4 ships email signup form, but no logged-in state.)
15. **Per-angler attribution to individual anglers.** "Anglers reporting" is a count, never a list.
