### Moon row color contract

| Element | Token | Hex | Opacity | Usage |
|---------|-------|-----|---------|-------|
| Sine curve line | `--color-text-muted` | `#475569` | 100% (1.0) | The moon-illumination line stroke |

| Midline reference (illumination = 0.5) | not drawn | — | — | Decision: **no midline drawn**. The shading geometry conveys the wave; an extra midline adds visual noise without clarifying the signal. (See §Visual Hierarchy "Sub-chart implementation note".) |

### Color-blind safety verification

Phase 6 uses ECharts' default categorical palette for catch-chart series (D-21 in `06-CONTEXT.md`, "color-blind-friendly"). The moon line color `#475569` (slate-600) is a **neutral desaturated dark blue-gray** — distinguishable from every color in the ECharts default categorical palette under deutan, protan, and tritan simulations because:

1. It is desaturated (chroma ≈ 12 in OKLCH); ECharts categorical defaults are saturated.
2. It is darker (lightness ≈ 38) than the muted surface background (`#f8fafc`, lightness ≈ 98), giving 5.4:1 contrast ratio on `--color-surface-muted` — exceeds WCAG AA for non-text graphical objects (3:1).
3. It already serves as the muted-text color in Phase 6, so its placement in the muted-foreground role is established.

The shading at `#cbd5e1` 35% over `#f8fafc` resolves to approximately `#e3e8ed` — sufficient contrast against `#f8fafc` (~1.3:1) to read as fill but not enough to compete with foreground series. This is **intentional**: the wave is reference, not data, and should not visually fight the catch line.

### Accent reservation (unchanged from Phase 6)

Phase 7 introduces no new accent usage. Specifically:

- The moon toggle does **not** use accent in its default (off) state.
- When the moon toggle is **active** (on), it uses the same selected-state styling as RangeStrip buttons: `bg-(--color-accent) text-white border-(--color-accent)`. This is *consistent* with the existing accent reservation list — selected-toggle is already an accent-eligible role per Phase 6.

**Updated "accent reserved for" list:**

1. Active ticker pill (Phase 6)
2. Active range button (Phase 6)

## Visual Hierarchy

The moon row is **subordinate** to the catch chart. Reading order on the explorer page after this phase:

1. Page title `Explorer`
2. Sticky `ExplorerHeader` (ticker pills → selector → range strip → **moon toggle**)
3. Catch chart (primary visual anchor — height unchanged: 280px mobile / 360px desktop)
4. **Moon row** (NEW, 36px, only when moon=on)
5. Caption (existing)
6. SpeciesBreakdownTable (boat ticker only, existing)

**When moon is off, step 4 is removed entirely from the DOM** — not hidden via CSS, not a 0-height div, not an empty grid row. The off-state DOM is byte-for-byte identical to Phase 6 (see §Off-state Guarantee).

### Sub-chart implementation note (advisory, not prescriptive)

Two viable approaches are documented in `07-CONTEXT.md` D-93 (Claude's discretion). The UI-SPEC does **not** dictate which to use, but specifies the visual contract that holds either way:

- The moon row sits flush below the catch chart (0px gap, no separator hairline).
- Both rows share the **same X-axis time domain** and the **same bucket alignment** (a vertical line through any X coordinate hits the same date in both rows).
- Only the **catch chart** renders X-axis date tick labels. The moon row hides its X-axis labels (`axisLabel.show: false`) to avoid duplication.
- The moon row hides its Y-axis entirely (`yAxis.show: false`). The Y-domain is implicit: trough = new moon (illumination 0), peak = full moon (illumination 1).
- Tooltip (axis-crosshair from Phase 6 D-22) **does not extend** into the moon row. The tooltip applies only to catch-chart series. (See §Copywriting Contract → "Tooltip behavior" for the explicit decision.)

If approach (a) — second `<Chart>` instance — is chosen, the two charts must be linked via `echarts.connect()` or a shared `axisPointer.link` group so axis-crosshair stays synchronized when implemented in the future. If approach (b) — single ECharts instance with `option.grid: []` array — is chosen, the second grid must have `gridIndex: 1` and reference `xAxisIndex: 1, yAxisIndex: 1` on the moon series.

## Component Anatomy

### 1. MoonToggle (NEW — inline button in ExplorerHeader, no new component file required)

A pill-style toggle button rendered immediately to the right of the RangeStrip on desktop, and on a new dedicated line below the RangeStrip on mobile. Visually matches a range button so the toggle reads as "another range-strip control."

**Placement decision:** Inside `ExplorerHeader.svelte`, in Row 3 (the range-strip row), **after** `<RangeStrip>` and **before** `<CustomDateInputs>`. This keeps all chart-shaping controls consolidated in one row and avoids consuming a precious mobile vertical row of its own.

```svelte
<!-- Inside ExplorerHeader.svelte Row 3, after <RangeStrip> -->
<div class="mt-2 md:mt-0 md:ml-2 inline-flex">
  <button
    type="button"
    role="switch"
    aria-checked={moon}
    aria-label="Show moon phases"
    onclick={() => onMoonChange(!moon)}
    class="min-h-11 shrink-0 rounded border px-3 py-2 text-sm font-semibold
           {moon
             ? 'bg-(--color-accent) text-white border-(--color-accent) hover:bg-(--color-accent-hover)'
             : 'bg-(--color-surface) text-(--color-text-muted) border-(--color-border) hover:bg-(--color-accent-bg) hover:text-(--color-accent) hover:border-(--color-accent)'}"
  >
    Moon
  </button>
</div>
```

**Why `role="switch"` instead of `aria-pressed`:** The Phase 6 ticker pills and range buttons use `aria-pressed` because they are members of a mutually-exclusive group (only one ticker selected; only one range selected). The moon toggle is **independent and binary** (on/off, not "this option vs. that option") — `role="switch"` with `aria-checked` is the more semantically correct ARIA pattern for binary on/off controls per WAI-ARIA 1.2.

**States** (mirrors RangeStrip state matrix from Phase 6 §Interaction States):

| State | Background | Text | Border |
|-------|-----------|------|--------|
| Off (default) | `--color-surface` | `--color-text-muted` | `--color-border` |
| Off, hover | `--color-accent-bg` | `--color-accent` | `--color-accent` |
| Off, focus-visible | `--color-surface` | `--color-text-muted` | 4px accent ring (via `app.css`) |
| On | `--color-accent` | white | `--color-accent` |
| On, hover | `--color-accent-hover` | white | `--color-accent-hover` |
| On, focus-visible | `--color-accent` | white | 4px accent ring |

**Mobile layout:** On mobile (<768px) the toggle wraps to a new line directly below the range strip via `mt-2`. On desktop (≥768px), `md:mt-0 md:ml-2` flips to inline placement at 8px gap from the strip's last button. This keeps the existing 3-row sticky-header structure on mobile (D-23 in 06-CONTEXT.md) while not adding a 4th row.

### 2. MoonRow (NEW — sub-chart below the catch chart)

Rendered conditionally in `+page.svelte` only when `filters.moon === true`.

```svelte
<!-- Inside +page.svelte, IMMEDIATELY after <Chart> (the catch chart) -->
{#if filters.moon}
  <Chart
    option={data.moonChartOption}
    height="36px"
    ariaLabel="Moon illumination over the same time range"
  />
{/if}
```

**ECharts option contract** (passed via the loader `data.moonChartOption`):

```typescript
{
  grid: { left: <same as catch chart>, right: <same as catch chart>, top: 0, bottom: 0 },
  xAxis: {
    type: 'category' | 'time',  // MUST match the catch chart's type
    data: <same buckets>,
    show: false,                 // hide tick labels (catch chart owns these)
    axisLine: { show: false },
    axisTick: { show: false },
    splitLine: { show: false }
  },
  yAxis: {
    type: 'value',
    min: 0, max: 1,              // illumination domain
    show: false,
    splitLine: { show: false }
  },
  series: [{
    type: 'line',
    smooth: true,                // sine curve
    showSymbol: false,
    sampling: 'lttb',            // downsample for long ranges (5Y/All) — fuzzy band per D-06 is honest about resolution loss; lttb still gives a real shape, not noise
    lineStyle: { color: 'var(--color-text-muted)', width: 1.5 },
    areaStyle: { color: 'rgba(203, 213, 225, 0.35)' },  // --color-border-strong @ 35%
    data: <illumination values, one per bucket>,
    silent: true,                // no hover, no click, no tooltip on this series
    animation: false             // sine is static — no animation regardless of reduced-motion
  }],
  tooltip: { show: false },      // moon row has no tooltip (see Copywriting Contract)
  animation: false               // double-belt-and-suspenders: no animations on this chart
}
```

**Critical alignment requirement:** The `grid.left` and `grid.right` of the moon row MUST match the catch chart's `grid.left` and `grid.right` exactly. If the values differ by even 1px, the moon row will visually drift from the catch buckets and the contract is broken. The loader is responsible for emitting both grids with identical horizontal padding.

### 3. ExplorerHeader.svelte (MODIFIED — add `moon` prop and `onMoonChange` callback)

Phase 7 extends the existing component with two new props:

```typescript
let {
  ticker, range, fromDate, toDate,
  onTickerChange, onRangeChange, onCustomDates,
  autoWidenNote, clampNote, selector,
  // NEW Phase 7 props:
  moon,                                // boolean — current toggle state
  onMoonChange                         // (next: boolean) => void
}: { ... } = $props();
```

The MoonToggle markup is added inside Row 3 immediately after `<RangeStrip>` and (where applicable) before the `{#if range === 'custom'}` block.

### 4. /explorer/+page.svelte (MODIFIED)

- Read `filters.moon` from loader data.
- Render `<Chart>` for the moon row only when `filters.moon === true` (no hidden div, no display:none — the DOM node simply does not exist when off).
- Pass `moon` and `onMoonChange` to `<ExplorerHeader>`.
- `onMoonChange(next)` calls `navigate({ ...currentFilters, moon: next })` — same `goto({replaceState:true, noScroll:true, keepFocus:true})` pattern Phase 6 already uses.

### MoonRow — interaction states

| Surface | Behavior |
|---------|---------|
| Hover (pointer) | **No hover state.** `silent: true` on the series. The catch chart's axis-crosshair tooltip does not extend into the moon row. |
| Click / tap | **No interaction.** The moon row is a pure visualization. Anglers wanting to toggle it use the MoonToggle. |

### Range / ticker change while moon is on

When the angler changes the range preset (1M → 3M → ... → All) or the ticker (boat → species → landing) **while moon is on**, the loader must:

1. Recompute the moon series for the new visible range using `src/lib/shared/moon.ts`.
2. Pass the new `moonChartOption` to the page.
3. The page re-renders both `<Chart>` instances on the same SvelteKit navigation tick — no double flicker.

This satisfies Phase 7 success criterion #2 (markers stay correctly positioned across range/ticker changes, no extra fetch). The moon series is recomputed in pure TS (D-07), so no DB roundtrip.

## Off-state Guarantee

Phase 7 success criterion #3: *"With moon overlay off, the chart looks identical to Phase 6 (no leftover artifacts)."* This is enforced by the following hard contract:

| Property | Off-state value | Off-state behavior |
|----------|-----------------|---------------------|
| Catch chart height | `280px` mobile / `360px` desktop | **identical to Phase 6** |
| Catch chart `grid` config | unchanged from Phase 6 | no extra `grid[1]` entries, no reserved bottom padding for a hidden row |
| Catch chart `xAxis` config | unchanged from Phase 6 | not modified to "share" with a non-existent moon row |
| DOM nodes below the catch chart | caption → SpeciesBreakdownTable (existing Phase 6 layout) | **no `<div>` placeholder, no `display:none` Chart instance, no skeleton** |
| URL search params | `moon` param **omitted entirely** when off | clean-URL principle (D-04 in 06-CONTEXT.md). `serializeExplorerFilters` only sets `moon=1` when `filters.moon === true`; default-off means no param. `/explorer` (clean URL) still resolves to "boat ticker, 1Y range, moon off." |
| Cache-Control headers | unchanged | moon being off has no cache impact (would only matter if on, and even then computation is cheap) |
| ECharts series count | same as Phase 6 (one per visible overlay series, capped at 6) | no hidden moon series sneakily injected |
| Bundle size | unchanged from Phase 6 (off-path) | `src/lib/shared/moon.ts` is server-side only; nothing in the client bundle changes when moon is off |

**Test guidance for the executor (advisory):** an integration test should assert that `/explorer` (clean URL) and `/explorer?moon=0` produce **identical** SSR HTML for the chart container — byte-for-byte except for the URL itself. If the rendered HTML differs in any way (extra DOM, different inline style, different aria-label), the off-state contract is violated.

### Reduced Motion

The sine curve is **static** — `animation: false` on the moon ECharts option. There is no animation to suppress. This is consistent with Phase 6's `Chart.svelte` reduced-motion handling and requires no additional user-preference branching.

The MoonToggle itself uses no CSS transitions beyond what Phase 6's button styles already declare; the global `prefers-reduced-motion: reduce` rule in `app.css` covers any inherited transition.

### Focus Ring

Inherited from `app.css` (`box-shadow: 0 0 0 2px var(--color-surface), 0 0 0 4px var(--color-accent)`). Applies to the MoonToggle automatically because it is a `<button>`. No new declarations needed.

### Touch Targets

MoonToggle: `min-h-11` (44px). Width: `px-3` (12px each side) + 4-character "Moon" label at 14px font ≈ 56px wide — exceeds 44px width on touch.

### Screen-reader Announcements

When the angler toggles moon on/off, the URL changes via `goto`. SvelteKit re-renders the page and the new `aria-checked` value is announced by VoiceOver / TalkBack / NVDA on next focus. No live-region announcement is added — the toggle's own `role="switch"` is sufficient under WAI-ARIA 1.2.

The MoonRow itself is announced as `"image: Moon illumination over the same time range"` when traversed. This is intentionally minimal — the moon row's purpose is visual, and a screen-reader user will get more useful information from the catch chart's existing aria-label and the underlying data than from a textual transliteration of a sine curve.

## Copywriting Contract

### Toggle label

```
Moon
```

**Rationale:** The header is space-constrained. "Moon" is the operator's voice (CLAUDE.md: "anglers familiar with the scene"; ROADMAP.md uses "moon-phase markers"). "Show moon phases" was considered but is too long for the range-strip rhythm — it would force the toggle onto its own row even on desktop, which (a) consumes vertical space, and (b) implies the toggle is more important than the chart it modifies. The shorter "Moon" matches the punchy "1M / 3M / All" range-strip rhythm.

The full description lives in `aria-label="Show moon phases"` so screen-reader users hear a complete phrase.

### aria-label for the toggle

```
Show moon phases
```

**Rationale:** Plain English (CLAUDE.md). "Lunar overlay" was rejected as jargon. "Show moon phases" is unambiguous about what the control does and is consistent with the verbatim-domain-language rule.

### aria-label for the MoonRow chart

```
Moon illumination over the same time range
```

**Rationale:** Tells a screen-reader user (a) what the visual represents (illumination, the continuous quantity), (b) why it is there (same time range as the catch chart above). Plain English; no astronomy jargon.

### Tooltip behavior

**Decision: NO moon row in the catch chart's tooltip.**

When the angler hovers a bucket on the **catch chart** with moon on, the tooltip shows the same content as Phase 6 (bucket label + per-series rows with value and `n=N`). The tooltip does **not** add a "Moon: full / new / waxing / waning" line.

**Rationale:**

1. CONTEXT.md "Claude's Discretion" sets the default to "don't add complexity unless the presentation feels incomplete without it." The visual sine curve directly above is sufficient — anglers can read the wave at the same X position they are hovering.
2. Adding a moon line bloats the tooltip vertically on mobile (already 6 visible series + bucket label).
3. The "phase" labels (full / new / first quarter / last quarter) are conceptual checkpoints — D-01 explicitly avoids drawing them as discrete glyphs because the curve *is* the data. Reintroducing them in the tooltip contradicts the chosen visual model.

**Consequence:** the moon series in the moon row uses `silent: true` (ECharts), so the catch chart's `axisPointer` does not extend into it and the catch tooltip does not gain a moon row. This is also the simplest implementation — no tooltip plumbing changes from Phase 6.

If post-launch user feedback requests phase names in the tooltip, that is a Phase 11 polish change, not a Phase 7 scope expansion.

### Off-state copy

None — the moon row simply isn't rendered. No "Moon overlay disabled" text, no placeholder, no skeleton.

### URL sharing copy

When an angler shares a URL with `?moon=1`, the recipient lands on the same view with moon on. No share-specific copy is needed in Phase 7 — Phase 8 (Sharing) will add the share UX. Phase 7's contribution is making sure the URL contract is honored end-to-end before Phase 8 builds on top.

### Empty / error / loading states

**Empty state:** Moon row is never empty if it is rendered — moon illumination is defined for every date. If the moon library throws or returns invalid values, the moon row simply does not render (treat as off). No new empty-state copy.

**Error state:** Same fallback — failure to compute moon data → render as off (graceful degradation), and log server-side. No user-facing error message in Phase 7. This intentionally trusts the angler: if the toggle is on but the data quietly fell back to off, the catch chart is unaffected and the angler can re-toggle.

**Loading state:** The moon row is computed by the loader and ships in the SSR response — no client-side fetch, no loading spinner. If approach (a) two-Chart-instance is chosen, the moon `<Chart>` shows the same `"Loading chart…"` text Phase 6's `Chart.svelte` already provides during ECharts dynamic-import. No new loading copy.

### Destructive actions

None in Phase 7. Toggling moon off is non-destructive.

## URL State Contract

`ExplorerFiltersSchema` in `src/lib/shared/urlState.ts` gains a single new field:

```typescript
moon: z.coerce.boolean().default(false)
// or, matching the existing boolStringField pattern:
moon: z.enum(['true', 'false', '1', '0']).transform(s => s === 'true' || s === '1').default('false')
```

(Exact Zod shape is the planner's call — the existing schema uses `boolStringField` for picker `rangeMode`; consistency suggests `boolStringField` here too. The contract requirement is: the field defaults to `false`, accepts `?moon=1` or `?moon=true` as on, and rejects garbage.)

**Serialization rule:** `serializeExplorerFilters` writes `moon=1` to the URL **only when `filters.moon === true`**. When moon is off, the param is omitted entirely. This preserves D-04 (clean URL on default landing) and the off-state guarantee.

**URL examples:**

| URL | Moon state |
|-----|-----------|
| `/explorer` | off (default) |
| `/explorer?ticker=boat&slug=pacific-voyager&range=1y` | off (omitted) |
| `/explorer?ticker=boat&slug=pacific-voyager&range=1y&moon=1` | on |
| `/explorer?moon=1` | on (other filters use defaults) |
