The full sample home loader (RESEARCH §"Home-Page Section Query"):

```typescript
// src/routes/+page.server.ts
import type { PageServerLoad } from './$types';
import { getDb } from '$lib/db/client';
import { homeSections } from '$lib/db/queries/home';
import { latestSuccessOrEmpty } from '$lib/db/scrapeRuns';
import { today, addDays, toPtTimeLabel } from '$lib/shared/dates';

export const load: PageServerLoad = async ({ setHeaders, locals }) => {
  const db = getDb();
  const toDate = today();
  const fromDate = addDays(toDate, -7);
  setHeaders({ 'cache-control': 'public, max-age=300' });
  const sections = homeSections(db, { fromDate, toDate, minTrips: 5, perSection: 5 });
  const lastScrape = latestSuccessOrEmpty(db);
  const lastScrapedLabel = lastScrape ? toPtTimeLabel(lastScrape.finished_at) : null;
  locals.logger?.info({ msg: 'home_loaded', sections: sections.length, fromDate, toDate });
  return { sections, fromDate, toDate, lastScrapedLabel };
};
```

The two-pass home query (RESEARCH §"Home-Page Section Query", lines 980-1052) — viable canonical trip types first, then top-N per section:

```typescript
// Pass 1 — viable canonical trip types
SELECT ${CANONICAL_TRIP_TYPE_EXPR} AS canonical_trip_type,
       COUNT(DISTINCT cr.source_date || '|' || cr.boat_id) AS trip_count
  FROM catch_reports cr
  ${ALIAS_JOIN_SQL}
 WHERE cr.source_date BETWEEN @fromDate AND @toDate
 GROUP BY canonical_trip_type
HAVING trip_count >= @minTrips
 ORDER BY trip_count DESC

// Pass 2 — top-N boats by fpa per canonical trip type, restricted to Pass-1 set
SELECT b.id AS boat_id, b.slug AS boat_slug, b.display_name AS boat_display_name,
       COUNT(DISTINCT cr.source_date) AS trip_count,
       SUM(cr.species_count) AS total_caught,
       SUM(cr.angler_count) AS total_anglers,
       SUM(cr.species_count) * 1.0 / NULLIF(SUM(cr.angler_count), 0) AS fpa,
       MAX(CASE WHEN tta.status = 'pending' THEN 1 ELSE 0 END) AS pending
  FROM catch_reports cr
  JOIN boats b ON b.id = cr.boat_id
  ${ALIAS_JOIN_SQL}
 WHERE cr.source_date BETWEEN @fromDate AND @toDate
   AND ${CANONICAL_TRIP_TYPE_EXPR} = @canonical
 GROUP BY cr.boat_id
 ORDER BY fpa DESC, b.display_name ASC
 LIMIT @topN
```

export const actions: Actions = {
  alias: async ({ request, cookies }) => {
    if (!verifyAdminCookie(cookies.get('fc_admin'))) return fail(401, { error: 'Not authorized' });

    upsertAlias(getDb(), {

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Anonymous public → `/` | No authentication; aggregated boat-aggregate data only. No PII flows into the loader. |
| Anonymous public → `/admin/*` | Untrusted; gate enforces signed cookie. Login form is the only public admin endpoint. |
| Operator browser → `/admin/trip-types` form action | Authenticated via fc_admin cookie. Form data flows into upsertAlias. |
| `process.env.ADMIN_PASSWORD` / `ADMIN_COOKIE_SECRET` → server | Module-load-time read. Missing → service misconfigured (503-ish, not stack trace). |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-08-02-01 | Spoofing | Admin login | mitigate | `crypto.timingSafeEqual` constant-time compare in checkPassword (Task 1). Length-leak mitigation: A2 test — return false immediately on length mismatch. Per RESEARCH A6: no rate limit at v1; mitigation = strong password + low-traffic site. Operator can add rate-limit middleware in a follow-up if needed. |
| T-08-02-02 | Tampering | fc_admin cookie | mitigate | HMAC-SHA256 over ADMIN_COOKIE_SECRET; `verifyAdminCookie` rejects tampered payload + tampered signature; uses `timingSafeEqual` to prevent timing attacks on signature comparison. |
| T-08-02-03 | Spoofing / Tampering | CSRF on admin form actions | mitigate | SameSite=Strict on fc_admin cookie + SvelteKit form actions include CSRF protection by default `[CITED: svelte.dev/docs/kit/form-actions]`. |

VALUES (@source_label, ...)` named bindings. Form-data values cast via `String(...)` before DAL call.
